يضم الخادم مضيف Model Context Protocol مدمجًا، وقسم `MCP` في واجهة الويب يستخدم لضبطه: يستطيع وكلاء الشيفرة (Claude Code وCodex وKimi Code وPi وOpenCode وQwen Code وDeepSeek Harness …) الاتصال من محادثاتهم الخاصة والعمل مباشرة على جهازك — قراءة الطرفيات وتشغيلها، بل وتشغيل EasyEDA Pro.

## إعدادات الخادم

فعّل خادم MCP واضبط:

- `Port` (الافتراضي `6180`) و`Bind Address` — `127.0.0.1` يُبقي نقطة النهاية على localhost؛ `0.0.0.0` يفتحها للشبكة؛
- `Access Token` — مطلوب للطلبات من غير localhost: على المتصلين البعيدين تقديمه كـ Bearer token، بينما تُقبل طلبات localhost دائمًا. لا يكون فارغًا أبدًا — التثبيت الجديد يأتي برمز عشوائي؛ زر النرد يعيد توليده وزر النسخ يخرجه؛
- `Stream Throttle` — الحد الأدنى للفاصل بين دفعات بث الشاشة إلى الوكلاء المتصلين.

تُطبَّق التغييرات عند `Save`؛ يعيد الخادم التحميل دون إعادة تشغيل.

## نقاط النهاية

تُخدَم كل مجموعة قدرات على عنوانها الخاص `http://localhost:{port}/{id}/mcp`:

- **Terminal MCP** (`/terminal/mcp`) — سطح الطرفية المدمج. يستطيع الوكلاء سرد الطرفيات وقراءة الشاشة المرئية وسجل التمرير وكتابة الإدخال الخام والمفاتيح المسماة وتغيير الحجم وانتظار المحثّ. تستهدف استدعاءات الأدوات طرفية واحدة بمعرّفها — انقر بزر أيمن على طرفية → `MCP` → `Copy Terminal ID` وألصق المعرّف في سياق الوكيل (انظر Terminal MCP في قسم Terminals)؛
- **EasyEDA Pro MCP** (`/easyeda/mcp`) — إضافة MCP مدمجة تربط EasyEDA Pro بالوكلاء: طقم أدوات ثابت صغير مع فهرس قابل للبحث لنداءات `eda.*`، يُمرَّر إلى امتداد موصّل EasyEDA عبر WebSocket. فعّل الإضافة أولًا في قسم `Addons` — تظهر نقطة نهايتها في القائمة بعد التثبيت، ويعرض الشارة ما إذا كانت خادمة الإضافة متصلة حاليًا. حقل `Timeout` في الإضافة يقيّد كل طلب مُجسَّر (ارفعه لعمليات EDA البطيئة)؛
- **إضافات MCP الأخرى** — أي إضافة مثبتة من نوع MCP تضيف نقطتها بالطريقة نفسها، مع شارة متصل/غير متصل حيّة.

اختر واجهة سطر أوامر الوكيل من القائمة المنسدلة أعلى القائمة؛ سيعطي زر النسخ بجانب أي نقطة نهاية أمر الإعداد الجاهز للتشغيل لهذا التطبيق.

## توصيل وكيل

لا حاجة أبدًا للصق الرمز يدويًا. يحتفظ الخادم بملف بيئة `Vibe Terminal MCP Bearer Token` مُولَّد تلقائيًا (انظر قسم Environment Variables) يُصدِّر `VTERM_MCP_TOKEN`؛ طبّقه على الطرفية قبل توصيل الوكيل ثم استخدم الأمر المنسوخ:

- **تطبيقات أوامر الصدفة** (Claude Code وCodex) — شغّل أمر `mcp add` المنسوخ في طرفية عادية. يقرأ Codex الرمز من `VTERM_MCP_TOKEN` عبر `--bearer-token-env-var` فلا يقع أي سر في سطر الأوامر؛
- **التطبيقات الحوارية** (Kimi Code وPi وOpenCode وQwen Code وDeepSeek Harness) — شغّل التطبيق مع تطبيق الملف ثم أرسل الموجّه المنسوخ داخل محادثته. يحدّث الوكيل إعدادات MCP مباشرة. يستخدم Kimi الخاصية `bearerTokenEnvVar`؛ ويستخدم Pi وOpenCode وQwen Code وDeepSeek Harness رمز Bearer من `VTERM_MCP_TOKEN`، لذلك لا يظهر الرمز نفسه في المحادثة.

داخل Pi وQwen Code تفحص `/mcp` الاتصالات.

تحتفظ بطاقة `Command Templates` أسفل الإعدادات بأوامر الإعداد لكل تطبيق: حرّر مدخلًا أو تجاوز مدمجًا أو أضف قوالب لواجهات أوامر وكلاء جديدة — تعرض المعاينة بالضبط ما سينتجه زر النسخ.
