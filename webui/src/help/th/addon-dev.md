การปรับแต่งมีสองระดับ: แพตช์ซอร์สของแอดออนที่มีอยู่ หรือเขียนตัวใหม่ตามแบบตัวในตัวแล้วอัปโหลด

## แพตช์ซอร์สแบบร้อน

ปุ่มดินสอบนการ์ดแอดออนใด ๆ เปิดซอร์ส JavaScript ให้แก้ การบันทึกจะเก็บ snapshot ที่เขียนทับต้นฉบับ — ทั้งแบบในตัวและที่อัปโหลด — และการเปลี่ยนแปลงมีผลทันทีไม่ต้องรีสตาร์ท เหมาะกับปรับ prompt แก้ URL หรือทดลองไอเดียบนระบบจริง

`Reset` ทิ้ง snapshot และกู้ซอร์สต้นฉบับ (เฉพาะตัวในตัว — ตัวที่อัปโหลดเป็นของคุณอยู่แล้ว)

![แก้ซอร์สแอดออน — snapshot ที่บันทึกเขียนทับต้นฉบับ](images/addon-edit-source.jpg)

## เขียนแอดออนของตัวเอง

แอดออนมีสองไฟล์:

- `<id>.json` — manifest: `id`, `name`, `description`, `author`, `email`, `date`, `type` และ `config_fields` (key, label, ชนิดช่อง, ค่าเริ่มต้น, คำอธิบาย) ที่ Web UI เปลี่ยนเป็นฟอร์ม；
- `<id>.js` — ซอร์ส: ไฟล์ JavaScript ธรรมดา (รันด้วยเอนจิน QuickJS ฝังตัว พร้อมสะพาน `addon.get_config()` ไปยังช่องที่ตั้งไว้) ส่งออกฟังก์ชันที่ type ของมันเรียก — เช่น `chat_completion()` สำหรับผู้ให้บริการ LLM, รายการเครื่องมือและการเรียกสะพานสำหรับแอดออน MCP

ทางเร็วสุดคือส่งออกแอดออนที่มีอยู่: ปุ่ม `Export` บนการ์ดดาวน์โหลด zip ที่รวม manifest กับซอร์สเข้าด้วยกัน เลือกตัวในตัวที่ใกล้เป้าหมายที่สุด (อยู่ใน `crates/vterm-server/src/addon/builtins/` ด้วย) แก้ id, name, type และฟังก์ชันที่ส่งออก แล้วติดตั้งผลลัพธ์ด้วย `Upload Addon` ตัวที่อัปโหลดลบได้อีกด้วยปุ่มถังขยะ

![ส่งออกแอดออน — manifest กับซอร์ส JavaScript เป็น zip เดียว](images/addon-export.jpg)

## ที่เก็บ

แอดออนที่อัปโหลดและ snapshot ซอร์สอยู่ในโฟลเดอร์ `addons/` ของไดเรกทอรีการตั้งค่าเป็น `<id>.json` + `<id>.js` จึงอยู่รอดการรีสตาร์ต สำหรับ id แบบในตัว มีเพียงการเขียนทับ `.js` ที่ถูกใช้ — ตัวในตัวเก็บ manifest ของมันเอง
