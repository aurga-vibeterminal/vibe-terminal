เซิร์ฟเวอร์มีโฮสต์ Model Context Protocol ในตัว และส่วน `MCP` ของ Web UI ใช้ตั้งค่ามัน: Code Agent (Claude Code, Codex, Kimi Code, Pi, OpenCode, Qwen Code, DeepSeek Harness ฯลฯ) เชื่อมต่อจากแชตของตัวเองแล้วทำงานบนเครื่องคุณได้โดยตรง — อ่านและควบคุมเทอร์มินัล และแม้แต่ใช้งาน EasyEDA Pro

## การตั้งค่าเซิร์ฟเวอร์

เปิดใช้ MCP server แล้วตั้งค่า:

- `Port` (ค่าเริ่มต้น `6180`) และ `Bind Address` — `127.0.0.1` จำกัด endpoint ไว้ที่ localhost; `0.0.0.0` เปิดให้เครือข่าย;
- `Access Token` — จำเป็นสำหรับคำขอที่ไม่ได้มาจาก localhost: ผู้เรียกจากระยะไกลต้องแนบมันมาเป็น Bearer token ส่วนคำขอจาก localhost อนุญาตเสมอ โทเคนไม่มีทางว่าง — การติดตั้งใหม่มาพร้อมโทเคนสุ่ม; ปุ่มลูกเต๋าสร้างใหม่ ปุ่มคัดลอกหยิบออกมา;
- `Stream Throttle` — ช่วงห่างขั้นต่ำระหว่างการดันสตรีมหน้าจอไปยัง agent ที่เชื่อมต่อ

การเปลี่ยนแปลงมีผลเมื่อกด `Save`; เซิร์ฟเวอร์โหลดใหม่แบบร้อนโดยไม่ต้องรีสตาร์ต

## Endpoint

แต่ละชุดความสามารถให้บริการที่ URL ของตัวเอง `http://localhost:{port}/{id}/mcp`:

- **Terminal MCP** (`/terminal/mcp`) — พื้นผิวเทอร์มินัลในตัว agent สามารถระบุเทอร์มินัล อ่านหน้าจอที่มองเห็นและประวัติเลื่อน พิมพ์อินพุตดิบและปุ่มที่ระบุชื่อ ปรับขนาด และรอพรอมป์ การเรียก tool กำหนดเป้าเทอร์มินัลด้วย Terminal ID — คลิกขวาที่เทอร์มินัล → `MCP` → `Copy Terminal ID` แล้ววาง ID ลงในบริบทของ agent (ดู Terminal MCP ในส่วน Terminals);
- **EasyEDA Pro MCP** (`/easyeda/mcp`) — แอดออน MCP ในตัวที่เชื่อม EasyEDA Pro เข้ากับ agent: ชุดเครื่องมือคงที่เล็กน้อยบวกแคตตาล็อกการเรียก `eda.*` ที่ค้นหาได้ ส่งต่อไปยังส่วนขยายตัวเชื่อมต่อ EasyEDA ผ่าน WebSocket เปิดใช้แอดออนในส่วน `Addons` ก่อน — endpoint จะปรากฏในรายการเมื่อติดตั้งแล้ว และป้ายแสดงว่า daemon ของแอดออนเชื่อมต่ออยู่หรือไม่ ฟิลด์ `Timeout` ของแอดออนจำกัดคำขอบนสะพานแต่ละรายการ (เพิ่มสำหรับงาน EDA ที่ช้า);
- **แอดออน MCP อื่น ๆ** — แอดออนชนิด MCP ที่ติดตั้งจะเพิ่ม endpoint ของตัวเองในแบบเดียวกัน พร้อมป้ายเชื่อมต่อ/ตัดการเชื่อมต่อแบบสด

เลือก CLI ของ agent ในเมนูแบบเลื่อนลงเหนือรายการ; ปุ่มคัดลอกข้าง endpoint จะให้คำสั่งตั้งค่าที่รันได้ทันทีสำหรับแอปนั้น

## เชื่อมต่อ agent

โทเคนไม่ต้องวางด้วยมือ เซิร์ฟเวอร์ดูแลโปรไฟล์สภาพแวดล้อม `Vibe Terminal MCP Bearer Token` ที่สร้างอัตโนมัติ (ดูส่วน Environment Variables) ซึ่ง export `VTERM_MCP_TOKEN`; นำไปใช้กับเทอร์มินัลก่อนเชื่อมต่อ agent แล้วจึงใช้คำสั่งที่คัดลอกไว้:

- **แอปคำสั่งเชลล์** (Claude Code, Codex) — รันคำสั่ง `mcp add` ที่คัดลอกในเทอร์มินัลปกติ Codex อ่านโทเคนจาก `VTERM_MCP_TOKEN` ผ่าน `--bearer-token-env-var` จึงไม่มีความลับหลุดไปในบรรทัดคำสั่ง;
- **แอปแบบสนทนา** (Kimi Code, Pi, OpenCode, Qwen Code, DeepSeek Harness) — เริ่มแอปโดยใช้โปรไฟล์แล้วส่งพรอมป์ที่คัดลอกไว้ในบทสนทนา Agent จะอัปเดตการตั้งค่า MCP โดยตรง Kimi ใช้ `bearerTokenEnvVar`; Pi, OpenCode และ Qwen Code ใช้โทเคน Bearer จาก `VTERM_MCP_TOKEN` โทเคนจึงไม่ปรากฏในแชต

ใน Pi และ Qwen Code ใช้ `/mcp` ตรวจสอบการเชื่อมต่อ

การ์ด `Command Templates` ใต้การตั้งค่าเก็บคำสั่งตั้งค่ารายแอป: แก้ไขรายการ ทับของในตัว หรือเพิ่มเทมเพลตสำหรับ CLI ใหม่ — ส่วนพรีวิวแสดงตรงตามที่ปุ่มคัดลอกจะสร้าง
