ตัววิเคราะห์เทอร์มินัลฝั่งเซิร์ฟเวอร์เฝ้าดูเอาต์พุตของเทอร์มินัล: ตรวจจับพรอมต์คำสั่ง จดจำการเสร็จสิ้นของงาน และด้วย LLM จำแนกว่าเทอร์มินัลกำลังแสดงอะไร `Auto Confirm` เป็นฟีเจอร์ที่ใช้มากที่สุด — เมื่อเทอร์มินัลหยุดที่พรอมต์ยืนยันธรรมดา (เช่น `Proceed? [Y/n]`) Enter จะถูกส่งแทนคุณ งานยาว ๆ จึงไม่ติดที่คำถามอีกต่อไป

## การตั้งค่า

ส่วน `Terminal Analysis` ของ Web UI:

- `Terminal observer` — สวิตช์หลักของการวิเคราะห์ฝั่งเซิร์ฟเวอร์;
- `Auto confirm` — ส่ง Enter เฉพาะพรอมต์ที่จำแนกว่าเป็น **การยืนยันธรรมดา**; คำถามอื่นไม่เคยถูกตอบอย่างปราณี;
- `Analysis delay (seconds)` — รอนานเท่าไรหลังเอเจนต์ว่างก่อนวิเคราะห์ หลีกเลี่ยงการเรียก LLM ซ้ำซ้อนระหว่างงาน;
- `Confirmation grace (seconds)` — ช่วงเวลาที่คุณสามารถเข้าควบคุมหลังตรวจพบการยืนยัน;
- `Notify on completion` — ส่งเหตุการณ์เมื่อเอาต์พุตถูกจำแนกว่างานเสร็จ (นำไปต่อกับการแจ้งเตือน)

> หมายเหตุบนหน้า: เมื่อโหมดอัตโนมัติของเอเจนต์เองเปิดอยู่ ควรปิด `Auto Confirm` ที่ไคลเอนต์เพื่อไม่ให้ระบบอัตโนมัติทั้งสองตอบทับกัน

## การพึ่งพา LLM

การจำแนกทำโดย LLM: เลือก `Provider` และกรอกข้อมูลรับรองในส่วน `LLM` (ใช้ร่วมกับการจำแนกเทอร์มินัล ข้อความคอมมิต Git ผู้ช่วยแชท และฟีเจอร์ AI อื่น) ไม่มี LLM ตัววิเคราะห์ยังทำงานได้แต่ความแม่นลดลง — ในกรณีนั้นให้ปิดการยืนยันอัตโนมัติ
