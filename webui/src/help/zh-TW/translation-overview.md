翻譯功能把用戶端裡遇到的文字變成你選擇的語言：AI 聊天回覆、提交訊息、程式碼註解，或程式碼編輯器與差異檢視中的任意選取範圍。翻譯模型設定在伺服器端完成——用戶端只負責傳送文字、呈現結果並快取，方便在原文與譯文之間來回切換。

## 哪裡可以使用翻譯

- **Copilot 聊天面板**——每則訊息的標頭（你的訊息、模型回覆和 `思考中…` 區塊）都有翻譯圖示。點擊一次將訊息內文替換為譯文；再點一次還原原文；
- **提交訊息草稿**——Git 面板的提交框在草稿超過一行後會顯示翻譯按鈕。它會把整段草稿就地翻譯，再點一次即可找回原稿；
- **提交詳情彈出視窗**——在 Git 歷史記錄中懸停某次提交會開啟詳情彈出視窗；雜湊值旁的翻譯圖示把提交訊息切換成你的語言；
- **程式碼編輯器與差異檢視**——選取任意內容（區塊選取也算），右鍵選擇 `翻譯`。行號欄中會出現一個地球徽章標記被翻譯的行，譯文卡片在選取範圍旁展開。

## 工作原理

1. 用戶端把文字傳給伺服器——若文字來自編輯器或差異檢視的選取範圍，還會附上檔名，讓模型知道該檔案使用哪種註解語法；
2. 伺服器的翻譯 LLM 將其翻譯為 Web 介面設定的目標語言。Markdown 格式（標題、清單、表格、程式碼區塊）會保留；檔案選取範圍中的註解標記（如 `//`、`#`）會被識別為裝飾並去除，程式碼與識別字原樣保留；
3. 用戶端把結果以 Markdown 呈現在請求來源處——聊天訊息就地替換，編輯器與差異選取範圍顯示在可捲動的卡片中。

## 前置條件

- 一台啟用了翻譯功能的伺服器——一次性設定見「伺服器設定」頁（Web 介面的 `LLM 設定`）；
- 一台連線到該伺服器的桌面用戶端。用戶端無需任何設定：所有介面共用同一份伺服器設定。

若翻譯未設定，用戶端會顯示伺服器傳回的錯誤（例如在譯文卡片中），而不是翻譯結果。
