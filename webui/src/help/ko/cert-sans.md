리프 인증서는 **주체 대체 이름(SAN)** 에 나열된 이름에만 유효합니다. 클라이언트가 연결할 때 URL의 호스트명 또는 IP는 이 항목 중 하나와 정확히 일치해야 합니다. 와일드카드도 접두사 매칭도 지원되지 않습니다. 이 페이지는 서버 측에서 해당 목록을 관리하는 방법을 다루며, 클라이언트 측 확인은 마지막 페이지「클라이언트 엄격 검증」을 참조하세요.

## 자동 검색

서버는 자신이 도달 가능한 이름(현재 호스트명과 활성 네트워크 인터페이스의 주소)을 지속적으로 검색하여 `자동 검색됨` 아래에 나열합니다. 이 항목은 머신을 따라가며 수동 편집이 불가능합니다. 네트워크 인터페이스를 추가하거나 호스트명을 바꾸면 다음 갱신 때 목록이 따라 바뀝니다.

## 추가 도메인 및 IP 주소

자동 검색이 모든 것을 알지는 못합니다. DDNS 이름, 스플릿 호라이즌 DNS 항목, NAT 뒤의 주소는 직접 나열해야 합니다. `추가 도메인 및 IP 주소` 아래에서 추가하세요.

1. 호스트명 또는 IP 주소(예: `server.home.arpa`, `10.0.0.8`)를 입력하고 `추가`를 누릅니다.
2. 클라이언트가 사용할 모든 이름에 대해 반복합니다. 불필요한 항목은 휴지통 버튼으로 제거합니다.
3. `최종 SAN 미리 보기`를 확인합니다. 자동 검색 항목과 수동 항목이 병합된 보기로, 다음 인증서에 포함될 이름입니다.
4. `저장 후 재발급`을 누릅니다. 저장하면 새 SAN 목록으로 90일짜리 새 리프 인증서가 서명되고 핫 리로드됩니다. 기존 연결은 유지되고 새 핸드셰이크는 즉시 새 인증서를 사용합니다.

## 수동 재발급과 상태

`서버 리프 인증서` 패널에는 현재 활성 인증서가 표시됩니다. 상태 배지, 주체, SHA-256 지문, 유효 기간, SAN 항목입니다. 상태 배지의 의미는 다음과 같습니다.

- `사용 가능` — 유효한 리프 인증서가 로드되어 사용 중입니다.
- `업데이트 실패` — 마지막 재발급이 실패했습니다. 이전 인증서가 계속 활성 상태이며 오류가 페이지에 표시됩니다.
- `생성되지 않음` — CA나 리프 인증서가 아직 없습니다. `CA 및 인증서 생성`으로 둘 다 만드세요.

`리프 인증서 재발급`은 자동 트리거를 기다리지 않고 즉시 새 리프 인증서를 서명합니다. 호스트명이나 인터페이스 변경 직후, 또는 웹 UI 밖에서 이루어진 SAN 수정을 반영할 때 유용합니다.

## 루트 CA 배포

엄격한 검증을 사용할 클라이언트에는 루트 CA의 공개 인증서가 필요합니다. `프라이빗 루트 CA` 카드에서 받으세요.

- `루트 CA 다운로드`는 PEM 파일을 저장합니다.
- `루트 CA 복사`는 PEM을 클립보드에 넣어 클라이언트의 CA 필드에 바로 붙여넣을 수 있게 합니다.

리프 인증서 갱신이나 SAN 변경에도 CA는 변하지 않습니다. 한 번 배포하면 충분합니다. 어디서든 엄격한 검증을 활성화하기 전에 이 페이지의 SHA-256 지문과 클라이언트가 받은 내용을 대조하세요(마지막 페이지「클라이언트 엄격 검증」참조).

> 다운로드와 클립보드에는 CA 공개 인증서만 포함되며 개인 키는 절대 포함되지 않습니다. 이 서버를 검증할 수 있어야 하는 사람에게만 전달하세요.
