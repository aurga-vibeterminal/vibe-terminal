翻訳は機能ごとの LLM ジョブで、サーバーで一度設定するだけです。任意のクライアントからの翻訳リクエスト——チャットメッセージ、コミット下書き、エディターと差分の選択範囲——はすべて同じ設定を通ります。

## 機能を有効にする

Web UI の `LLM` セクションを開き、`翻訳` カードを見つけます:

1. `LLM 翻訳を有効化` をオンにします;
2. `プロバイダー` を選びます——ドロップダウンには `アドオン` セクションで**有効**になっている LLM アドオンだけが表示されます（内蔵の **OpenAI Compatible LLM** プロバイダーで大半のケースをカバーできます）;
3. `プロバイダー設定` のフィールドを埋めます（内蔵プロバイダーでは `Base URL`、`API Key`、`Model`、任意で `Extra Body`、トークン上限、`Timeout`）;
4. すべての訳文の言語となる `翻訳先の言語` を選びます。

設定は機能無効の間も保存されますが、スイッチをオンにして初めてサーバーに適用されます。無効のままでは、クライアントのリクエストは *"translation addon is not configured or disabled"* で失敗します。

## ターゲット言語

ターミナルや Git 機能と異なり、翻訳に `自動` オプションはありません——常にリストから明示的な 1 言語へ翻訳します（English、简体中文、繁體中文、Deutsch、Español、Français、日本語、한국어、Nederlands、Polski、Português、Русский、ไทย、Tiếng Việt、العربية、Bahasa Indonesia、Bahasa Melayu、Українська）。この設定はサーバー全体に適用され、切り替えは新しいリクエストにのみ影響します。未設定の場合は英語にフォールバックします。

![ターゲット言語のドロップダウン](images/translation-server-language.jpg)

## プロバイダー資格情報の再利用

`プロバイダー設定` 見出し横のコピー/ペーストボタンは、同じプロバイダーアドオンを使う機能カード間でフィールド値を複製します——あるカード（例えば Git コミットメッセージ）でプロバイダーを選んで埋め、**コピー** を押し、翻訳カードで **貼り付け** します。

## モデル選び

翻訳は短くレイテンシ敏感なプロンプトです——高速なモデルが大型推論モデルに勝ります。OpenAI 互換エンドポイント（Ollama、vLLM、llama.cpp）越しの **Qwen3.5 9B**、または API 経由の **DeepSeek V4 Flash** がどちらもよく機能します。サーバーはリクエストごとに最大 60 秒待ちます。遅いローカルモデルではプロバイダーフィールドの `Timeout` を大きくしてください。

> 思考モードは数秒のレイテンシを加えるだけで品質に寄与しません——`Extra Body` で無効にしてください。例えば Qwen は `{"enable_thinking": false}`、DeepSeek は `{"thinking": {"type": "disabled"}}`。
