Каждый терминал — полноправный участник MCP (Model Context Protocol): внешние агенты управляют терминалами через MCP-инструменты сервера — перечислить терминалы, прочитать экран, выполнить команды, дождаться завершения — позволяя привычному агенту кодинга работать с настоящими интерактивными оболочками.

## Терминальные MCP-инструменты сервера

Вокруг терминальных сессий MCP-клиент может:

- `list_terminals` — все открытые терминалы; `get_terminal` — заголовок, cwd и состояние приложения одного терминала;
- `get_screen` — текущий видимый текст экрана; `get_scrollback` — недавние строки истории;
- `send_command` — выполнить командную строку (Enter добавляется); `send_input` — сырой текст без Enter (подтвердить `y`, заполнить формы); `send_key` — именованные клавиши (Enter, Ctrl+C, стрелки);
- `clear_terminal` — очистить буфер; `resize_terminal` — изменить размер PTY; `wait_terminal` — блокировать, пока терминал не освободится.

## Адресация терминала: Terminal ID

Вызовы инструментов адресуются по Terminal ID. Правый клик внутри терминала → `MCP` → `Copy Terminal ID`, затем вставьте ID вашему агенту, чтобы он управлял именно этим терминалом.

## Подключение приложения агента одним кликом

Подменю `MCP` также перечисляет приложения агентов, обнаруженные на сервере (CLI редакторов и т. п.). Клик по приложению вводит готовую команду `mcp add` в терминал — **без завершающего перевода строки**; проверьте её и нажмите Enter сами, чтобы зарегистрировать MCP-службу этого сервера у этого агента. Запри скрываются, пока приложение уже работает в сессии, чтобы текст не попал в его интерфейс.

> Типичный цикл: скопировать Terminal ID агенту → `send_command` запускает сборку → `wait_terminal` до готовности → `get_screen` читает результат. Вместе с автоподтверждением (см. главу о терминалах) долгие интерактивные задачи выполняются почти без присмотра.
