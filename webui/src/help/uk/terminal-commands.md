Швидкі команди пришпилюють команди build/test/deploy проєкту в контекстне меню термінала — один клік для запуску, доступні всюди. Команди ведуться на репозиторій у `.vterm/commands.json` у корені репозиторію.

## Створення commands.json

Клацніть правою в терміналі → `Commands`:

- коли репозиторій сесії ще не має commands.json, меню пропонує єдиний запис `Generate commands.json` — клацання змушує сервер визначити тип проєкту (npm / Cargo / .NET / Xcode / Gradle-Android / загальний) і записати обережний стартовий шаблон. Наявний непорожній файл **ніколи не перезаписується**;
- розташування файлу: `.vterm/commands.json` у корені Git-репозиторію (поточна робоча директорія для не-Git тек).

## Доведення

Згенерований шаблон містить лише звичайні команди виявленого типу проєкту. Нехай ваш код-агент (напр. агент редактора, підключений до MCP цього сервера) прочитає проєкт і доведе файл:

```json
{
  "commands": [
    { "name": "Build", "command": "cargo build --release" },
    { "name": "Test verbose", "command": "cargo test -- --nocapture",
      "env": { "RUST_LOG": "debug" } },
    { "name": "Package (Windows)", "command": "./packaging/windows/package.bat",
      "os": "win" }
  ]
}
```

Масив верхнього рівня теж приймається; `env` необов'язковий і задає змінні перед виконанням команди; застарілий ключ `value` читається. Необов'язкове поле `os` обмежує запис операційною системою, на якій запущено `vterm-server`: використовуйте `"win"` для Windows, `"linux"` для Linux або `"osx"` для macOS. Якщо `os` пропущено, встановлено в `"all"` або містить нерозпізнане значення, запис доступний на всіх платформах. Сервер стежить за CWD і змінами commands.json та транслює їх — відкрийте меню знову, і нові команди там.

## Запуск

Права кнопка → `Commands` → клацніть запис, щоб виконати його в тому терміналі (необов'язковий env застосовується спершу). Меню недоступне, поки застосунок агента працює в сесії, щоб текст команди не потрапляв у його UI.

## Приклад: build і встановлення Android через Wi-Fi

Повний прохід на Gradle-Android-проєкті: пришпильте налаштування бездротового ADB і потік build-встановлення в контекстне меню, потім перезберіть застосунок одним кліком.

**1. Перемкнути телефон на бездротовий ADB.** Ці дві команди вводяться раз на пристрій — `adb tcpip 5555`, поки телефон на USB, потім `adb connect` з адресою телефону:

![Термінал — перемикання Android-телефону на бездротовий ADB через adb tcpip 5555 і adb connect](images/terminal-commands-adb-setup.gif)

**2. Нехай код-агент пише команди.** Відкрийте код-агента проєкту (тут Claude Code) у терміналі й попросіть додати команди build і встановлення — він читає структуру проєкту і записує елементи в `.vterm/commands.json`:

![Термінал — Claude Code редагує commands.json з командами build і встановлення APK](images/terminal-commands-agent-edit.mp4)

**3. Зберіть і встановіть з меню.** Розділіть термінал, щоб вивід build мав власну панель, потім правою → `Commands` → запис — Gradle збирає APK і встановлює його на телефон через Wi-Fi:

![Термінал — розділення панелі і запуск команди Android build та встановлення з контекстного меню](images/terminal-commands-split-run.mp4)
