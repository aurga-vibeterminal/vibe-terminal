Інтелект панелі Git рухає LLM: повідомлення комітів одним кліком, читання diff за підтримки ШІ і розв'язання конфліктів агентом, hunk за hunk-ом. Усе це спирається на провайдера LLM, налаштованого у веб-інтерфейсі.

## Налаштування провайдера

Відкрийте розділ `LLM` веб-інтерфейсу:

- виберіть `Provider` і заповніть його облікові дані (поля визначає маніфест провайдера); налаштування глобальне — класифікація термінала, повідомлення комітів Git, чат-асистент та інші функції ШІ ділять того самого провайдера;
- провайдери — аддони типу LLM: звичайні вбудовані, а власні можна вивантажити як zip у розділі `Addons` (маніфест оголошує поля налаштувань, які веб-інтерфейс перетворює на форму).

![Розділ LLM веб-інтерфейсу — виберіть провайдера і заповніть його облікові дані](images/git-llm-provider-config.jpg)

## Функції LLM у Git

- **Генерація повідомлення коміту** — клацніть кнопку ШІ біля скриньки коміту; LLM читає staged diff і пише повідомлення, що друкується в скриньку з анімацією. Повідомлення лишається редагованим — комітьте лише коли задоволені;
- **Аналіз diff** — кнопка-іскра в заголовку вигляду diff аналізує поточний diff;
- **ШІ-агент конфліктів** — режим ШІ редактора злиття rebase розв'язує hunks по одному з поясненнями та впевненістю (див. Розв'язання конфліктів).

![Згенероване ШІ повідомлення коміту, надруковане в скриньці коміту](images/git-llm-commit-message.jpg)

> LLM читає вміст репозиторію лише для продукування тексту; коміти і злиття завжди відбуваються, коли ви їх підтверджуєте.
