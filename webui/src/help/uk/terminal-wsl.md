Є два способи користуватися WSL у Windows: легкий додає shell WSL як термінальний профіль, повний встановлює vterm-server усередині WSL. Перший дає лише shell; другий відкриває керування файлами, панель Git, MCP і все інше.

## Легкий спосіб: термінальний профіль WSL

У Windows **термінальні профілі WSL завантажуються автоматично**: при старті сервер виявляє `wsl.exe` і перелічує встановлені дистрибутиви, додаючи по одному запису профілю на дистрибутив до списку (напр. `Ubuntu (WSL)`; загальний запис `WSL` з'являється, коли дистрибутивів немає).

Щоб скористатися, просто виберіть запис WSL у меню профілів рядка заголовка клієнта — дистрибутив запускається й одразу ставить вас у його термінал, як відкриття локального.

Обмеження: такі сесії виконуються на сервері боці Windows — **провідник файлів, панель Git, змінні середовища та інше в клієнті не працюють** (вони оперують семантикою файлової системи Windows і не бачать файлової системи Linux у WSL).

## Повний спосіб: встановити vterm-server усередині WSL

Ставтеся до WSL як до окремої Linux-машини і встановіть headless vterm-server. Сайт пропонує однорядковий скрипт — вставте його в термінал WSL:

```bash
curl -fsSL https://vterminal.dev/install.sh | bash
```

Скрипт автоматично:

1. Виявляє середовище WSL/headless і завантажує **headless** vterm-server у `~/.local/vterm`;
2. Встановлює **системну службу користувача systemd** і одразу запускає її — вона виконується при кожному вході (включно зі стартом WSL), ручний запуск не потрібен;
3. Додає `~/.local/vterm` до вашого PATH.

> Коли systemd у WSL вимкнено, скрипт вказує додати `[boot]` `systemd=true` до `/etc/wsl.conf`, виконати `wsl --shutdown` боці Windows і перезапустити інсталятор.

## Відкриття сторінки налаштувань

У WSL:

```bash
vterm-server --open
```

Команда друкує адресу веб-інтерфейсу (`http://localhost:<config-port>/`) і намагається відкрити браузер (у WSL через `wslview`, типовий браузер Windows). Завдяки переспрямуванню localhost WSL2 **відкриття тієї ж адреси у браузері Windows** працює так само добре. Поки сервер працює, надрукована адреса містить одноразовий токен входу (`?ticket=...`, виданий через локальний сокет), тож сторінка відкривається вже автентифікованою.

## (Необов'язково) Спільний доступ до сервера WSL у реле хоста

Якщо машина Windows також запускає vterm-server (як реле), сервер WSL може причепитися під нього, щоб клієнт бачив обидві «машини» через одне локальне з'єднання:

1. У веб-інтерфейсі сервера Windows клацніть QR-код, щоб скопіювати рядок спільного доступу;
2. Відкрийте веб-інтерфейс сервера WSL (адреса з попереднього розділу), клацніть кнопку вставки, що з'являється біля поля `Relay Address`, щоб автозаповнити адресу й ключ, потім `Apply`;
3. Поки vterm-server Windows працює, клієнт бачить термінали, файли та Git сервера WSL під локальним реле.

> У типовій NAT-мережі WSL2 WSL досягає хоста Windows за адресою хоста з погляду WSL (типовий шлюз — nameserver у `cat /etc/resolv.conf`); з дзеркальною мережею працює `localhost`. Деталі реле — у розділі Relay.
