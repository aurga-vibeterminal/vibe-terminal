Кожен термінал — повноправний громадянин MCP (Model Context Protocol): зовнішні агенти керують терміналами через MCP-інструменти сервера — перелічити термінали, прочитати екран, виконати команди, дочекатися завершення — дозволяючи агенту кодування, яким ви вже користуєтеся, оперувати справжніми інтерактивними shell-ами.

## Термінальні MCP-інструменти сервера

Навколо термінальних сесій клієнт MCP може:

- `list_terminals` — усі відкриті термінали; `get_terminal` — заголовок, cwd і стан застосунку одного термінала;
- `get_screen` — поточний видимий текст екрана; `get_scrollback` — недавні рядки історії;
- `send_command` — виконати командний рядок (Enter додається); `send_input` — сирукий текст без Enter (підтвердити `y`, заповнити форми); `send_key` — іменовані клавіші (Enter, Ctrl+C, стрілки);
- `clear_terminal` — очистити буфер; `resize_terminal` — змінити розмір PTY; `wait_terminal` — блокувати, поки термінал не звільниться.

## Адресація термінала: Terminal ID

Виклики інструментів цілиться в термінал за його Terminal ID. Правою в терміналі → `MCP` → `Copy Terminal ID`, потім вставте ID агентові, щоб він керував саме цим терміналом.

## Реєстрація застосунку агента одним кліком

Підменю `MCP` також перелічує застосунки агентів, виявлені на сервері (CLI редакторів і подібні). Клацання на застосунок друкує готову команду `mcp add` у термінал — **без завершального нового рядка**; перегляньте її й натисніть Enter самі, щоб зареєструвати MCP-службу цього сервера в того агента. Записи ховаються, поки застосунок уже працює в сесії, щоб текст не потрапляв у його UI.

> Типовий цикл: скопіюйте Terminal ID агентові → `send_command` запускає build → `wait_terminal` до готовності → `get_screen` читає результат. Разом з Автопідтвердженням (див. розділ терміналів) довгі інтерактивні задачі виконуються майже без нагляду.
