Домашній та офісний широкосмуговий доступ типово йде з динамічним публічним IP, що змінюється без попередження. DDNS тримає фіксований домен наведеним на поточний IP машини — клієнтам та іншим серверам досить пам'ятати ім'я, ніколи адресу.

## Як це працює

![Архітектура DDNS — менеджер періодично виявляє локальний IP, аддон оновлює DNS-запис через API провайдера, клієнти з'єднуються доменом](diagram/ddns)

Увесь конвеєр працює автоматично у фоні сервера:

1. **Менеджер DDNS** освіжається у фіксованому циклі (типово кожні 5 хвилин, регулюється змінною середовища `TERMINAL_SERVER_DDNS_POLL_INTERVAL_SECS`); збереження налаштувань спричинює негайне освіження, і нічого не працює, поки службу вимкнено;
2. **Виявлення локального IP** читає спершу обраний мережевий інтерфейс, падаючи до виявлення за маршрутами, і фільтрує результат за налаштуванням `IP Family` (IPv4 / IPv6 / подвійна);
3. **Аддон DDNS** — ізольований JS-скрипт — отримує розшифровану конфігурацію і поточний IP та викликає API DNS-провайдера через HTTP. Вбудований аддон Cloudflare, скажімо, шукає зону за доменом і переписує записи A / AAAA на поточний IP, видаляючи застарілі записи, коли зникає сімейство адрес;
4. **Клієнти** розв'язують домен до найновішого IP і з'єднуються ім'ям.

## Налаштування

Відкрийте розділ `DDNS` веб-інтерфейсу:

1. Увімкніть `Enable`. Можете також лишити службу вимкненою, поки заповнюєте все — вимкнена служба зберігає свою конфігурацію, але ніколи не виконується;
2. виберіть провайдера під `Provider`; `Cloudflare DDNS` вбудований;
3. заповніть поля провайдера (приклад Cloudflare):
   - `Email` — пошта облікового запису Cloudflare;
   - `API Token` — токен із правом Zone → DNS → Edit;
   - `Domain` — кореневий домен зони, напр. `example.com`;
   - `Subdomain` — ім'я запису в зоні, напр. `sub` для `sub.example.com`; лишіть порожнім для кореня зони;
4. у `Network Interface & IP` виберіть `Interface` та `IP Family`. `Dual Stack` вимагає, щоб інтерфейс мав і IPv4-, і IPv6-адресу;
5. клацніть `Save`, потім `Sync Now` для перевірки. `Sync Status` показує останній пропушений IP і час синхронізації, а при невдачі — повідомлення про помилку аддона.

## Безпека

Облікові дані провайдера (API-токени) шифруються перед зберіганням (`enc-v2:`) і розшифровуються лише в пам'яті, поки аддон працює; аддони виконуються в ізольованому JS-середовищі, чиєю єдиною здатністю є вихідний HTTP.

## Розширення провайдерів

Провайдери — аддони: JSON-маніфест (що оголошує поля налаштувань, які веб-інтерфейс перетворює на форму) плюс JS-скрипт, що викриває `run()`. Вбудований `cloudflare-ddns` — еталонна реалізація; власних провайдерів можна вивантажити як zip у розділі `Addons`.

## Разом з іншими функціями

- Щойно домен розв'язується, QR-код розділу `Server` може перемкнути `Connection Type` на `DDNS Domain`, щоб клієнти сканували доменне з'єднання;
- інші сервери можуть поставити `wss://your-domain:port` у свій `Relay Address`, щоб гнати ланцюг реле доменом (див. розділ Relay).
