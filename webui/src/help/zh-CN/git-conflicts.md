rebase 或合并遇到冲突时,面板切换为冲突视图:左侧冲突文件列表,右侧合并编辑器。冲突文件也会以 `!` 徽标出现在 `CHANGES` 列表中——点击即可直接进入该视图（而非普通 diff）。编辑器提供四种解决模式,随时切换。

![冲突视图 —— 左侧文件列表,右侧合并编辑器](images/git-conflicts-view.jpg)

## 冲突文件列表

按状态分组:自动合并成功的文件（自动暂存）与仍需手动处理的文件。点击文件进入编辑器;解决一个,列表实时更新,直到清空。

## 四种解决模式

- **Merge**（默认）:冲突按块（hunk)呈现,逐块选择 `采用 ours` / `采用 theirs` / 手动编辑合并结果,所见即所得;
- **Split**:把 diff 拆成更细的行级片段,同一块里可以分段采纳双方;
- **Raw**:带 `diff3` 冲突标记（`<<<<<<<` / `=======` / `>>>>>>>`）的原文编辑,适合手工精修;
- **AI**:逐块代理解决——LLM 分析每块冲突,给出解决方案、解释与置信度卡片;可以输入指令约束解决策略（如"以 theirs 为主,保留日志语句"）,支持暂停后在其他模式微调再继续,已解决的块自动跳过。

所有模式下,解决结果都直接写入会话中的文件并暂存,与手动编辑无异。

## 与 rebase 的衔接

冲突全部解决后,继续执行 rebase 的下一个提交;若想放弃整个变基,随时可以中止回到变基前的状态。
